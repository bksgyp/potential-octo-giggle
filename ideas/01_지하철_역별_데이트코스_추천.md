# 01. 지하철 역별 데이트코스 추천

- 한 줄 정의(초안): 수도권 뚜벅이 커플을 위한 지하철 노선도 기반 데이트 스팟 추천 플랫폼
- 지원 구분: 서비스/앱/플랫폼
- 상태: 검토 중
- 노션 원문: https://app.notion.com/p/yup6786/3c2959f514e480788b35ed2042740acf (#1)

## 문제 (노션 원문 요약)
- 수도권 거주 장수 커플(1년 이상)은 갈 만한 곳을 대부분 가봐서 새 데이트 장소를 찾기 어렵다.
- 뚜벅이 커플은 대중교통, 특히 수도권 교통망의 중심인 지하철로 이동한다.
- 데이트마다 "오늘은 어디 가지?" 고민이 반복되고, 커플 간 불화로 번질 수 있다.
- 기존 대안: 네이버 지도, 인스타그램·릴스 검색, 데이트 코스 블로그. 역 단위로 탐색하는 도구는 없다.

## 예상 유저
- 데이트 장소를 고민하는 커플 (핵심 사용자)
- 연극, 맛집, 카페 등 본인 업장을 홍보하려는 사장님 (광고주)

## 서비스 기획 (노션 원문 요약)
- 지하철 노선도를 기본 UI로 운영. 데이트 장소와 후기가 많을수록 역의 추천도가 시각적으로 올라감.
- 역 클릭 시 인근 데이트 스팟을 지도 / 리스트 / 카테고리별로 표시.
- 관련 릴스·쇼츠를 하단에 함께 추천 (Fleek 앱에서 영감).
- 방문한 장소는 체크 후 별점·후기 작성. 공정성을 위해 방문 후 일주일 안에만 작성 가능.
- 사장님은 비용을 내고 업장을 광고. 광고 장소는 일반 장소와 다르게 표시 (네이버 지도에서 영감).
- 수도권 지하철로 시작, 이후 대전·광주·부산 지하철과 고속철도로 확장.

## 3개월 MVP (검토 의견)
- 범위: 특정 노선 1~2개(예: 2호선)만 대상으로 역 선택 → 스팟 리스트 → 후기 작성까지 동작하는 웹앱.
- 데이터: 초기 스팟은 팀이 직접 수집(공공데이터 + 수동 큐레이션). 릴스 연동은 MVP 이후로 미룸.
- 150만원 사용 예: 지도 API·서버 이용료, UI 디자인 외주, 초기 사용자 테스트 홍보물.
- 필요 기술: 웹 프론트엔드, 지도 API, 간단한 백엔드·DB. 팀 보유 여부 확인 필요.

## 수익 모델
- 업장 광고(노출 상위 배치, 강조 표시) 과금.
- 확장 시 제휴 예약·쿠폰 수수료 가능.

## 리스크와 미해결 질문
- 콜드 스타트: 후기가 쌓이기 전에는 추천도 시각화가 비어 보인다. 초기 시드 데이터 확보 방안 필요.
- 네이버 지도·카카오맵의 "주변" 기능과 무엇이 결정적으로 다른지 한 문장으로 답해야 한다. 현재 답은 "역 단위 탐색 + 커플 특화 후기".
- 릴스·쇼츠 연동은 플랫폼 API 제약이 크다. MVP에서 제외.
- 후기 작성 기한(방문 후 일주일)을 검증할 방법(위치 인증 등)이 필요하다.
- 광고주 확보는 사용자 수가 먼저 필요하다. 프로그램 기간 내 매출 시연은 어렵다.
