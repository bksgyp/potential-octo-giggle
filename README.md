# comradar

커뮤니티를 매시간 읽고, 사람들이 실생활에서 겪는 불편을 찾아, 4시간마다
사업 가설까지 붙인 한 장짜리 보고서로 돌려주는 멀티 에이전트 프레임워크.

> 이 저장소는 2026년 2학기 아랩 액셀러레이팅 프로그램 저장소입니다.

## 무엇을 하는가

```
 클리앙   ─┐
 디시     ─┤
 뽐뿌     ─┼─▶ 수집 에이전트 (커뮤니티당 하나, 병렬, 서로 격리) ─▶ SQLite
 reddit×2 ─┘                                                        │
                                                                    ▼
                                                             분석 에이전트
                                                       (테마로 묶고 추세 판정)
                                                                    │
                        노션 <사업화 아이디어> ─▶ 사업화 에이전트     │
                                                (신규 가설 + 기존 아이디어 대조)
                                                                    │
                                                                    ▼
                                                             보고 에이전트
                                                                    │
                                                         reports/YYYY-MM-DD-HHMM.md
                                                         reports/…-HHMM.html
```

에이전트는 넷이고, 각자 하는 일이 다릅니다.

| 에이전트 | 개수 | 하는 일 |
|---|---|---|
| 수집 | 커뮤니티당 하나 | 자기 커뮤니티의 **신규 글만** 읽고 불편 사례를 뽑는다. 다른 커뮤니티는 보지 못한다. |
| 분석 | 하나 | 모든 수집 결과를 원인이 같은 것끼리 테마로 묶고, 이전 구간과 비교해 추세를 판정한다. |
| 사업화 | 하나 | 테마를 사업 가설로 바꾸고, 노션에 이미 있는 아이디어를 이번 관측에 비추어 다시 판정한다. |
| 보고 | 하나 | 헤드라인, 세 줄 요약, 지금 결정할 것을 쓴다. 레이아웃은 코드가 담당한다. |

수집 에이전트를 커뮤니티마다 격리한 것은 의도적입니다. 모든 커뮤니티를 보는
수집 에이전트는 곧바로 커뮤니티를 가로지르는 결론을 쓰기 시작하는데, 그것은
분석 에이전트의 일입니다.

샘플 출력: [`reports/sample.md`](reports/sample.md) (모델 호출 없이
`python scripts/demo_report.py`로 다시 만들 수 있습니다.)

## 두 개의 주기

- **수집은 매시간.** 이미 본 글은 SQLite에 기록되어 다시는 모델에 들어가지
  않습니다. 매시간 같은 첫 페이지를 읽어도 비용이 드는 것은 새 글뿐입니다.
- **보고는 4시간마다.** 한 시간치 신규 글로는 추세와 우연을 구분할 수 없습니다.
  `comradar run`을 매시간 호출해도 보고서는 4시간에 한 번만 나옵니다.
  주기 판단은 도구가 하므로 cron은 하나만 걸면 됩니다.

둘 다 `config/communities.yaml`의 `run.report_interval_hours`와
`run.window_hours`로 바꿉니다.

## 시작하기

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .

export ANTHROPIC_API_KEY=sk-ant-...     # 또는 `ant auth login`
export NOTION_TOKEN=ntn_...             # 사업화 대조용. 없으면 로컬 사본을 씁니다.

comradar doctor                          # 설정·소스 연결·아이디어 목록 점검
comradar run --fetch-only                # 모델 호출 없이 수집 경로만 확인
comradar run --force-report              # 첫 보고서
```

명령은 다음과 같습니다.

| 명령 | 용도 |
|---|---|
| `comradar run` | 매시간 호출용. 수집하고, 보고 주기가 되었으면 보고서까지. |
| `comradar collect` | 수집만. 보고서는 만들지 않는다. |
| `comradar report` | 새로 수집하지 않고, 저장된 관측만으로 보고서를 다시 만든다. |
| `comradar loop --interval 1h` | 프로세스 안에서 반복. 서버 없이 노트북에서 돌릴 때. |
| `comradar doctor` | 설정, 소스 연결, 포트폴리오 로드를 점검한다. |
| `comradar history` / `prune` | 실행 기록 확인, 오래된 관측 정리. |

## 감시 대상 커뮤니티

트래픽이 큰 곳 위주로 국내 3, 해외 2를 기본값으로 두었습니다.

| 커뮤니티 | 어댑터 | 고른 이유 |
|---|---|---|
| 디시인사이드 실시간베스트 | `rss` | 국내 최대 트래픽 커뮤니티, 생활 주제 유입이 넓다 |
| 클리앙 모두의공원 | `rss` | 생활 밀착 게시판, 글의 서술이 길어 원인 파악이 쉽다 |
| 뽐뿌 자유게시판 | `rss` | 소비·생활비 마찰이 자주 드러난다 |
| r/mildlyinfuriating | `reddit` | 사소하지만 반복되는 불편이 주제인 서브레딧 |
| r/LifeProTips | `reddit` | 사람들이 쓰고 있는 우회책이 모인다. 우회책이 많다는 것은 제품이 없다는 뜻이다 |

**국내 RSS 주소는 실제 응답을 확인하지 못했습니다.** 이 저장소를 만든 환경에서
외부 네트워크가 막혀 있었고, 커뮤니티 피드 주소는 사이트 개편으로 바뀝니다.
처음 켤 때 `comradar doctor`로 확인하고, 실패하면 해당 사이트의 RSS 주소를 찾아
`options.url`만 바꾸면 됩니다. 어댑터 코드는 건드릴 필요가 없습니다. 설정 파일
아래쪽에 예비 소스(루리웹, Hacker News, Lemmy, Discourse)를 꺼 둔 채로
준비해 두었으니 `enabled: true`로 바꿔 자리를 메울 수 있습니다.

각 사이트의 이용약관과 `robots.txt`를 확인할 책임은 운영자에게 있습니다. 이
도구는 공개 피드와 공개 API만 읽고, 로그인하지 않으며, 요청 사이에 지연을 둡니다.
`http.user_agent`는 실제로 연락 가능한 값으로 바꾸세요. Reddit을 포함한 여러
사이트가 정체를 밝히지 않는 클라이언트를 차단합니다.

### 소스 어댑터

`rss`, `reddit`, `hackernews`, `lemmy`, `discourse`, `json` 여섯 개가 있습니다.
전용 어댑터가 없는 API는 `json` 어댑터에 필드 매핑만 적어 주면 붙습니다.
커뮤니티를 추가하는 일은 설정을 고치는 일이지 코드를 고치는 일이 아닙니다.

## 노션 아이디어 대조

사업화 에이전트는 노션 페이지 **`사업화 아이디어`** 의 첫 번째 표(종합 비교)를
읽어, 이번 구간 관측이 기존 아이디어를 지지하는지 부정하는지 판정합니다. 신규
아이디어도 그 페이지와 **같은 25점 척도**(문제 절실함 / 시장 크기 / 차별성 /
실행 가능성 / 수익성)로 채점하므로, 신규와 기존을 같은 자에 놓고 볼 수 있습니다.

준비:

1. <https://www.notion.so/my-integrations> 에서 내부 통합을 만들고 토큰을 복사합니다.
2. 그 토큰을 `NOTION_TOKEN` 환경변수에 넣습니다.
3. 노션에서 `사업화 아이디어` 페이지를 열고 `⋯ → 연결`에서 그 통합을 연결합니다.

토큰이 없거나 노션이 응답하지 않으면 `config/ideas.yaml`의 로컬 사본으로
대조를 계속합니다. 노션 읽기에 성공하면 그 사본을 자동으로 갱신하므로,
오프라인 경로도 계속 최신 상태로 유지됩니다.

판정은 신호이지 결론이 아닙니다. 커뮤니티 언급은 문제가 존재한다는 증거이지
제품이 팔린다는 증거가 아니며, 프롬프트에도 그렇게 못박아 두었습니다.

## 예약 실행

**서버 cron (권장)**

```
0 * * * * /path/to/repo/scripts/run_hourly.sh >> /var/log/comradar.log 2>&1
```

**GitHub Actions** — `.github/workflows/monitor.yml`이 매시간 돌면서 새 보고서를
커밋합니다. `ANTHROPIC_API_KEY`, `NOTION_TOKEN`, 선택적으로 `SLACK_WEBHOOK_URL`을
저장소 시크릿에 넣으세요. 중복 수집을 막는 상태 DB는 액션 캐시에 보관되는데,
캐시는 만료될 수 있습니다. 만료되면 이미 본 글을 다시 분석하게 되어 그 회차
비용만 늘고 결과가 틀려지지는 않습니다. 예약 실행 자체가 지연되거나 건너뛸 수
있으므로, 지연을 견디지 못하는 운영이라면 cron 쪽이 낫습니다.

## 비용

네 역할 모두 기본은 `claude-opus-5`입니다. 비용을 줄여야 한다면 호출 수가 가장
많은 수집 에이전트부터 `models.collector.effort`를 낮추고, 그래도 부족하면
모델을 바꾸세요. 품질 저하는 보고서에 그대로 드러나므로 바꾼 뒤 며칠은 결과를
비교해 보는 편이 좋습니다.

비용을 억제하는 장치가 세 개 들어 있습니다. 신규 글만 분석하는 중복 제거,
역할별 시스템 프롬프트에 걸어 둔 프롬프트 캐시, 그리고 커뮤니티당 게시물 수와
불편 사례 수 상한입니다. 모든 보고서 각주에 그 회차의 토큰 사용량이 찍힙니다.

## 이 프레임워크가 하지 않는 것

- **검증하지 않습니다.** 커뮤니티에서 자주 언급된다는 것은 시장이 있다는 뜻이
  아닙니다. 보고서의 `2주 안에 할 검증` 항목이 그다음 단계입니다.
- **수집 실패를 숨기지 않습니다.** 막힌 커뮤니티는 그 회차의 각주에 이름과
  실패 사유가 그대로 남습니다.
- **근거 없는 항목은 버립니다.** 수집 에이전트가 존재하지 않는 게시물을 가리키면
  그 항목은 조용히 폐기됩니다. 보고서의 모든 인용에는 실제 URL이 붙습니다.

## 개발

```bash
pip install -e ".[dev]"
pytest            # 59개. 네트워크도 API 키도 쓰지 않습니다.
```

테스트는 소스 어댑터, 중복 제거, 네 에이전트, 렌더러, 그리고 가짜 소스와 가짜
모델로 도는 전체 파이프라인을 덮습니다.
